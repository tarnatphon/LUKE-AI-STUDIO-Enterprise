# Social Agency — “โพสต์นี้จะขึ้นเองไหม” และสาเหตุที่ยังไม่ขึ้น

> เอกสารนี้ตอบคำถามที่แอปเคยเงียบใส่: วางแผนโพสต์ไว้แล้ว **ทำไมมันไม่ขึ้น**
> ใช้คู่กับ [`linkedin-posting.md`](./linkedin-posting.md) (ขั้นตอนโพสต์จริง) และ
> [`forum-and-community-posting.md`](./forum-and-community-posting.md) (ช่องทางอื่น)

## 1. ความจริง 4 ข้อที่ต้องรู้ก่อน

1. **ตัวตั้งเวลาอยู่ในตัวแอป** ไม่ใช่บริการเบื้องหลัง — แอปปิด = ไม่มีใครสั่งให้โพสต์
2. **ตัวตั้งเวลารับเฉพาะรายการ `planned` / `ready`** — รายการที่รออนุมัติ (`needs_review`)
   ระบบตั้งใจไม่ส่งให้เอง
3. **ถึงเวลาแล้วแต่คะแนนไม่ผ่าน หรือภาพยังไม่ถูกตรวจ** → เวิร์กโฟลว์ *หยุดรอคน* ไม่ใช่ส่ง
   (แล้วไม่มีใครบอกว่าเหตุผลคืออะไร — รอบนี้แก้แล้ว)
4. **เลยกำหนดเกิน 2 ชั่วโมง** → รายการกลายเป็น `missed` และ**ระบบจะไม่ลองใหม่เอง**

`planned` ที่ไม่มีอะไรขวางจึงไม่ใช่คำสัญญา — ต้องผ่านด่านคะแนน AI Check (≥ `settings.threshold`,
ค่าเริ่มต้น 80) และด่านตรวจภาพ (ถ้าโพสต์มีรูป) ณ เวลาที่รัน

## 2. ป้ายในปฏิทิน: “จะขึ้นเองไหม”

ทุกการ์ดในปฏิทินมีบรรทัดคำตอบสั้น ๆ (`postOutlook()` ใน
`app/frontend/src/social-agency/lib.js` — ที่เดียว ใช้ร่วมกับหน้ารายการ การ์ดแจ้งเตือน
และสคริปต์) ชี้ที่ป้ายเพื่ออ่านเหตุผลเต็ม:

| ป้าย | หมายความว่า | ต้องทำอะไร |
| :--- | :--- | :--- |
| **● จะขึ้นเอง** | ตัวตั้งเวลาเดินอยู่ ปิด dry-run แล้ว ยังไม่ถึงเวลา | ไม่ต้องทำ — เปิดแอปค้างไว้จนถึงเวลา |
| **⚠ ไม่ขึ้นจริง** | ยังเปิด **dry-run** ของช่องทางนั้น | ปิด dry-run ที่ Connectors เมื่อพร้อม |
| **⚠ ไม่ขึ้น** + “ตัวตั้งเวลาหยุดอยู่” | ไม่มีใครสั่งให้รัน (แอปปิด/กดหยุด) | กด ▶ มุมขวาบน แล้วเปิดแอปค้างไว้ |
| **⚠ ไม่ขึ้น** + “ด่านตรวจภาพ” | ถึงเวลาจะหยุดรอคนตรวจภาพ | ตรวจภาพแล้วกด “ยืนยันภาพแล้ว + อนุมัติ” |
| **⚠ ไม่ขึ้น** + “TikTok” | ยังไม่ได้ยินยอมเป็นรายโพสต์ (โดยเจตนา) | เปิดรายการแล้วทำขั้นยินยอม |
| **⚠ ไม่อัตโนมัติ** | รออนุมัติ — ไม่มีใครอนุมัติ = ไม่ขึ้น | กดอนุมัติในหน้ารายการ/การ์ดแจ้งเตือน |
| **⚠ เลยเวลา** | เลยมาไม่ถึง 2 ชม. — tick ถัดไปรันให้แบบช้า | รอ หรือ “รันเลยตอนนี้” |
| **⚠ ไม่ขึ้น** + “เลยกำหนด” | เกิน 2 ชม. — tick ถัดไปจะตั้งเป็น `missed` | “รันเลยตอนนี้” ถ้ายังต้องการ |
| **⚠ ไม่ขึ้น** (“พลาดโพสต์”) | ระบบเลิกลองแล้ว | **“ส่งเลยตอนนี้”** |

การ์ดที่เผยแพร่แล้วจะไม่แสดงป้ายซ้ำ (สถานะบอกอยู่แล้ว)

## 3. หน้ารายการโพสต์: คำตอบเดียวกันพร้อมเหตุผล

เปิดรายการ → ใต้บรรทัดสถานะมีกล่อง **“จะขึ้นเองไหม”** บอกสถานะจริง + เหตุผล + ทางออก
เช่น

```
⏰ รออนุมัติ — จะไม่ขึ้นเองจนกว่าจะอนุมัติ
   เวลาของโพสต์นี้ผ่านมา 1 ชม. 20 นาทีแล้ว · อนุมัติแล้วระบบจะส่งจริงทันที
```

## 4. แจ้งเตือนเมื่อถึงเวลาแล้วยังไม่ขึ้น

- **ในแอป:** การ์ดเหนือแท็บ ขึ้นเมื่อรายการเลยเวลามา **≥ 5 นาที** และยัง `needs_review`
  พร้อมปุ่ม **“อนุมัติและเผยแพร่เลย”** (ถ้าติดด่านตรวจภาพ ปุ่มจะกดไม่ได้และพาไปดูรูปก่อน
  — การยืนยันภาพเป็นการตัดสินใจของคน ไม่ใช่ผลข้างเคียงของการอนุมัติ)
  ปิดการ์ดได้เฉพาะรอบนั้น
- **ใน log:** tick แรกที่พบจะพิมพ์
  `[social-agency] ถึงเวลาแล้วยังไม่อนุมัติ: …` **ครั้งเดียวต่อรายการ**
  (`entry.approvalReminderAt` จำไว้ ไม่เตือนซ้ำทุกนาที)
- **บน macOS:** ถ้าเปิด `client.settings.notify` จะมี notification ด้วย (เดิมมีแต่ darwin)

## 5. `missed` มีปุ่ม “ส่งเลยตอนนี้”

เดิมต้องรู้เองว่าต้องเลื่อนเวลา — ตอนนี้ปุ่มเดียวจบ:

- `POST /api/social-agency/send-now` → `sendMissedNow()` ใน runtime
- เลื่อน `date`/`time` ของรายการมา **เวลาปัจจุบัน (Asia/Bangkok)** เก็บของเดิมไว้ใน
  `entry.rescheduledFrom` (สูงสุด 5 ครั้ง) แล้วรันเวิร์กโฟลว์ตามปกติ
  (`trigger: "send-now"`) — ด่านตรวจภาพ/คิวอนุมัติทำงานเหมือนการกด “รันเลยตอนนี้”
- ปุ่มอยู่ในหน้ารายการ (สถานะ `missed`) และในการ์ดแจ้งเตือน
- ไม่ยอมให้ส่งซ้ำรายการที่กำลังรัน/เริ่มส่ง TikTok ไปแล้ว และไม่ใช้กับรายการที่ยังไม่พลาด
  (นั่นคือ “รันเลยตอนนี้” อยู่แล้ว)

## 6. สถานะตัวตั้งเวลาในหน้าแอป

- **หัวหน้าแอป (ทุกแท็บ):** `ตัวตั้งเวลาทำงานอยู่ · tick ล่าสุด 12 วินาทีที่แล้ว · โพสต์ถัดไปใน 1 ชม.`
  หรือ `ตัวตั้งเวลาหยุดอยู่`
- **แท็บภาพรวม:** การ์ดเต็ม — สถานะ, tick ล่าสุด, รอบการทำงาน (60 วินาที), งานที่กำลังรัน,
  เขตเวลา, คิวถัดไป, จำนวนรายการที่เลยเวลาแล้วรออนุมัติ
- **“ทำงานอยู่แต่ tick ล่าสุดนานเกิน 3 นาที”** ขึ้นเตือนสีส้ม — timer object ยังอยู่ได้
  แม้ loop จะค้าง จึงไม่รายงานว่าเขียวอย่างเดียว

ข้อมูลทั้งหมดมาจาก `getSchedulerStatus()` ของ runtime (`GET /api/social-agency/scheduler`)

## 7. สคริปต์: `social-agency-why-not-posted.cjs`

```bash
node scripts/social-agency-why-not-posted.cjs --list                  # ทุกรายการที่ยังไม่ออกเอง
node scripts/social-agency-why-not-posted.cjs --entry ENTRY_ID        # เจาะทีละรายการ
node scripts/social-agency-why-not-posted.cjs --client thai-modern-bags
node scripts/social-agency-why-not-posted.cjs --entry ENTRY_ID --json
```

ตัวอย่าง `--list` (เรียงตามเวลาที่ควรโพสต์ — เวลา · ช่องทาง · ลูกค้า · สถานะ):

```

  3 รายการ · รออนุมัติ 0 · พลาด 0 · dry-run 3

    → node scripts/social-agency-why-not-posted.cjs --entry cal-6d740565-3244
  ✗ 30 ต.ค. 2569 18:00 · LINE · Thai Modern Bags Co.,Ltd. · planned
    …
  ✗ 31 ต.ค. 2569 09:00 · Instagram · Thai Modern Bags Co.,Ltd. · planned
    …
══════════════════════════════════════════════════════════════════
```

- บรรทัดแรกของแต่ละรายการคือ **เวลาที่ควรโพสต์ (เวลาไทย) · ชื่อช่องทางเต็ม · ชื่อลูกค้า ·
  สถานะ** ส่วน `--entry`/`--client` ใช้ ID ที่อยู่ในบรรทัด `→` ด้านล่าง
- รายการที่ “จะขึ้นเอง” ไม่ถูกนับเป็นปัญหา จึงไม่โผล่ในลิสต์ (ใช้ `--json` ถ้าต้องการทุกอย่าง)
- ถ้ามีรายการเดียว CLI จะแสดงรายละเอียดเต็มเหมือน `--entry` ให้เลย

ตัวอย่าง `--entry` (รายละเอียดเต็ม):

```
══ ทำไมโพสต์นี้ยังไม่ขึ้น ═══════════════════════════════════════════
  ลูกค้า: Thai Modern Bags Co.,Ltd. (thai-modern-bags) · กำลังใช้งาน
  รายการ: cal-1abc6b9e · 2026-10-29 08:00 · LinkedIn · SSB-013 · กระเป๋าใส่รองเท้า
  สถานะ: รออนุมัติ (needs_review)
  ควรโพสต์เมื่อ: 29 ต.ค. 2569 08:00 (เลยมา 1 ชม. 31 นาที)
  แอปเปิดอยู่ตอนนั้นไหม: ใช่ — แอปเปิดอยู่และตัวตั้งเวลาเดินอยู่ (tick ล่าสุด …)
  ตัวตั้งเวลาตอนนี้: ตัวตั้งเวลาทำงานอยู่ · tick ล่าสุด 2 นาทีที่แล้ว

  ด่านที่ติด (2):
    1. ยังไม่มีคนอนุมัติ — รายการอยู่ในคิวอนุมัติ …
    2. ด่านตรวจภาพ: ยังไม่ได้ตรวจภาพในหน้าโพสต์
  คะแนน: AI Check 48 / เกณฑ์ 80 ✗ · ไวรัล 62 / เกณฑ์ 60 ✓
  ช่องทาง LinkedIn: dry-run ปิด → ส่งจริงได้ · ทดสอบล่าสุด …

  สรุป: ✗ ยังไม่มีคนอนุมัติ — ตัวตั้งเวลาไม่ส่งรายการที่รออนุมัติให้เอง
  ทำอะไรต่อ:
    → ในแอป: เปิดรายการนี้แล้วกด "อนุมัติและเผยแพร่" …
    → ตรวจ/ยืนยันภาพจาก terminal: node scripts/social-agency-review-images.cjs --confirm ENTRY_ID
```

- **อ่านอย่างเดียว 100%** — ไม่เปลี่ยนสถานะ ไม่เริ่มเวิร์กโฟลว์ ไม่เผยแพร่
  (ต่างจาก `social-agency-review-images.cjs --confirm` ที่เขียนผลตรวจภาพ)
- ตอบครบตามที่ถาม: สถานะ · เวลาที่ควรโพสต์ · **แอปเปิดอยู่ไหมตอนนั้น** · ด่านไหนติด ·
  คะแนนเท่าไร · dry-run เปิดไหม + token ทดสอบล่าสุดเมื่อไร
- `ENTRY_ID` / `CLIENT_ID` คือช่องที่ต้องแทนด้วยค่าจริง — **อย่าพิมพ์ `<id>`** (zsh จะอ่าน `<`
  เป็น redirect) และถ้าพิมพ์ `cal-…` ตามตัวอย่าง เครื่องมือจะบอกว่าเป็นตัวอย่าง ไม่ใช่ ID จริง

## 8. Heartbeat: หลักฐานว่าแอปเปิดอยู่ตอนนั้นไหม

ไฟล์เล็ก ๆ ที่ runtime เขียน (ไม่มีข้อมูลลับ):

```
app/runtime-state/social-agency/scheduler-heartbeat.json
```

```json
{
  "version": 1,
  "pid": 51234,
  "tickMs": 60000,
  "timezone": "Asia/Bangkok",
  "startedAt": "2026-10-29T01:00:12.000Z",
  "lastTickAt": "2026-10-29T02:31:00.000Z",
  "stoppedAt": null,
  "previousRun": { "startedAt": "…", "lastTickAt": "…", "stoppedAt": "…" },
  "gaps": [{ "from": "2026-10-28T23:00:00.000Z", "to": "2026-10-29T01:00:12.000Z", "ms": 7212000 }]
}
```

- เขียนตอน **start / ทุก tick / stop** — ถ้าเขียนไม่ได้จะเตือนใน log และทำงานต่อ
  (heartbeat เป็นข้อมูลวินิจฉัย ไม่ใช่เหตุให้หยุดโพสต์)
- **gaps** = ช่วงที่แอปไม่ได้ทำงานจริง (ห่างกันเกิน 3 นาที) เก็บ 20 ช่วงล่าสุด
- ถามว่า “ตอน 08:05 แอปเปิดไหม” → ตรวจรอบปัจจุบัน → gaps → รอบก่อนหน้า (`previousRun`)
  ด้วย tolerance 3 นาที (ตัวเลขเดียวกับที่แอปเรียกว่า “ค้าง”)
- **ไม่มีไฟล์ = ไม่มีหลักฐาน** (ไม่ใช่ “แอปปิด”) — สคริปต์จะตอบว่า “ยังไม่มีบันทึก”
  ซึ่งคือกรณีของเครื่องที่อัปเดตขึ้นมาใหม่และยังไม่เคยเปิดตัวตั้งเวลา

## 9. ข้อจำกัดที่ยังเหลือ

| เรื่อง | ความจริง |
| :--- | :--- |
| โพสต์ตอนแอปปิด | ทำไม่ได้โดยดีไซน์ — heartbeat บอกได้แค่ว่า “ตอนนั้นแอปเปิด/ปิด” |
| การันตีว่าจะขึ้น | ไม่มี — คะแนน AI Check/ไวรัล และด่านตรวจภาพ ตัดสินตอนรัน ถ้าไม่ผ่านจะเข้าคิวอนุมัติ (และตอนนี้บอกล่วงหน้าว่าเป็นเช่นนั้น) |
| heartbeat ของเวอร์ชันก่อน | ยังไม่มีไฟล์ → CLI ตอบ “ไม่มีข้อมูล” จนกว่าจะเปิดแอปหนึ่งรอบ |
| dry-run | ระบบยัง “รัน” และบันทึกผล แต่ไม่ส่งขึ้นเครือข่าย — ป้ายจะบอกว่า “ไม่ขึ้นจริง” |
