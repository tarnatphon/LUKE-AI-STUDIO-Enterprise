# โพสต์เข้า “ฟอรัม/ชุมชน” ด้วย API — ทำได้จริงแค่ไหน และเริ่มยังไง

อัปเดตข้อมูล: **ตุลาคม 2026** · ใช้ร่วมกับโหนด “โพสต์อัตโนมัติ” และ “โพสต์คลิกเดียว”
ในหน้า **Luke AI Workflow** · ต่อจากเอกสาร `free-high-da-publishing-platforms.md`
(16 ช่องทางแรก) — รวมกันตอนนี้ **24 ช่องทาง**

เอกสารนี้ตอบคำถามที่คนถามบ่อยที่สุดก่อนซื้อเครื่องมือ auto‑post:
*“ให้ระบบไปตั้งกระทู้ในฟอรัม/เพจกลุ่มเองได้ไหม”*

คำตอบตรง ๆ มีสามระดับ และการแยกให้ชัดคือหัวใจของเอกสารนี้:

| ระดับ | คืออะไร | ทำได้ในแอปนี้ |
| :--- | :--- | :--- |
| **A. ฟอรัมที่คุณเป็นเจ้าของ** | Discourse / XenForo / NodeBB / Flarum / phpBB / WordPress ของบริษัทเอง | **ยิง API จริงได้** — คีย์ของคุณเอง สิทธิ์ของคุณเอง |
| **B. แพลตฟอร์มเปิดที่สมัครเองได้** | Bluesky, WordPress.com, Blogger, DEV, Telegraph | **ยิง API จริงได้** — ไม่ต้องรออนุมัติ |
| **C. ฟอรัม/กลุ่มที่คนอื่นเป็นเจ้าของ** | Pantip, Reddit, Facebook Groups, ฟอรัมทั่วไป | **ไม่มี API ให้โพสต์** — เตรียมข้อความ + เปิดหน้าเขียนให้ แต่ต้องกดเอง |

ถ้าเครื่องมือไหนบอกว่าทำข้อ C ได้แบบอัตโนมัติ ให้ถามต่อทันทีว่า “บัญชีใคร เป็นเจ้าของ
คีย์ใคร” — คำตอบจะบอกทุกอย่าง (ดูหัวข้อ 5)

---

## 1. ใช้ยังไงในแอป (3 ขั้น)

1. เปิด **Luke AI Workflow** → เพิ่มโหนด `AI Chat` (เขียนเนื้อหา) → เพิ่มโหนด
   **โพสต์อัตโนมัติ** แล้วเลือกช่องทางในกลุ่ม **“ฟอรัม/เว็บของเราเอง”** หรือ **Bluesky**
2. ใส่ค่าในกล่องคีย์ของช่องทางนั้น — เก็บที่
   `app/runtime-state/ai-workflow/publish-credentials.json` สิทธิ์ `0600`
   **ไม่เคยถูกส่งกลับไปที่เบราว์เซอร์ และไม่ถูกบันทึกลงประวัติการรัน**
   กด **ทดสอบ (dry-run)** เพื่อดู request จริงที่ระบบจะยิง (คีย์ถูกปิดเป็น `[set]`)
3. รัน workflow — ระบบโพสต์จริงแล้วคืนลิงก์ของกระทู้/โพสต์กลับมาใน artifact

ช่องทางฟอรัมทุกตัวมี **ขีดจำกัดที่ระบบเราบังคับก่อน** (หัวข้อ 3) และมีสวิตช์
**“เซิร์ฟเวอร์นี้อยู่ในเครื่อง/ในบ้าน”** สำหรับฟอรัมที่รันบนเครื่องหรือใน LAN

---

## 2. ตารางช่องทางที่เพิ่มเข้ามา (8 ช่องทาง)

“ชนิดลิงก์” ของช่องที่คุณเป็นเจ้าของ **ขึ้นกับค่าที่คุณตั้งในฟอรัมเอง** — ตารางนี้บอก
ค่าที่พบบ่อยที่สุด ไม่ใช่การรับประกัน · WordPress ที่ติดตั้งเองค่าเริ่มต้นคือ dofollow
แต่ปลั๊กอิน SEO ส่วนใหญ่จะเติม nofollow ให้เมื่อเห็นว่าลิงก์ออกเยอะ

| ช่องทาง | กลุ่ม | ลิงก์ | ต้องมี | โพสต์อัตโนมัติ | เหมาะกับ |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Bluesky** | โซเชียล | nofollow | App Password (ฟรี) | **API** | ประกาศสั้น, สายเทค |
| **WordPress (ติดตั้งเอง)** | ฟอรัม/เว็บของเรา | dofollow | Application Password | **API** | บทความหลักบนโดเมนตัวเอง |
| **Discourse** | ฟอรัม/เว็บของเรา | ตามที่ตั้ง | Api-Key + Api-Username | **API** | ชุมชนลูกค้า, KB ภายใน |
| **XenForo** | ฟอรัม/เว็บของเรา | ตามที่ตั้ง | XF-Api-Key (super admin) | **API** | ฟอรัมองค์กร, ไทยหลายแห่ง |
| **NodeBB** | ฟอรัม/เว็บของเรา | ตามที่ตั้ง | Bearer token + cid | **API** | ชุมชนนักพัฒนา |
| **Flarum** | ฟอรัม/เว็บของเรา | ตามที่ตั้ง | access token | **API** | ฟอรัมเล็กที่ติดตั้งง่าย |
| **phpBB** | ฟอรัม/เว็บของเรา | ตามที่ตั้ง | X-API-Key (extension) | **API** | บอร์ดไทยรุ่นเก่า |
| **Pantip** | โซเชียล | nofollow | บัญชี + ยืนยันตัวตน | **คลิกเดียว (ตั้งใจ)** | คำถาม/รีวิวที่มีคนค้นเจอ |

เพิ่มจากของเดิม: **Bluesky** เป็นแพลตฟอร์มฟรีที่ “สมัครแล้วโพสต์ได้ทันที” ที่สุดในลิสต์
ทั้งหมด — ไม่มี app review ไม่มีค่าใช้จ่าย ข้อจำกัดคือ 300 ตัวอักษร (นับเป็น grapheme
ภาษาไทยจึงไม่ถูกตัดกลางสระ/วรรณยุกต์)

## 3. ขีดจำกัดที่ระบบบังคับ (และทำไมต้องมี)

แพลตฟอร์มทุกเจ้าจำกัดความถี่แบบเงียบ ๆ (throttle, ซ่อนโพสต์, แบน) ระบบเราจึงตั้ง
เพดานของตัวเองให้ต่ำกว่านั้น เพื่อให้ workflow ที่รันซ้ำไม่พาไปถึงจุดนั้นก่อน:

| ช่องทาง | โพสต์/วัน | เว้นระยะขั้นต่ำ |
| :--- | --: | --: |
| Bluesky | 30 | 30 วินาที |
| WordPress (ติดตั้งเอง) | 20 | 60 วินาที |
| Discourse | 10 | 5 นาที |
| XenForo / NodeBB / Flarum / phpBB | 10 | 5 นาที |
| Pantip | ตามกฎเว็บ (1 กระทู้/วันสำหรับสมาชิกอีเมล) | — |

เมื่อชนเพดาน ระบบจะ **ไม่ยิง request เลย** และบอกว่า “รออีกกี่วินาที” หรือ
“โควตาวันนี้ครบแล้ว” · การนับเก็บเป็น **timestamps เท่านั้น**
(`app/runtime-state/ai-workflow/publish-rate.json` — ไม่มีข้อความ ไม่มีคีย์)
และ dry-run ไม่กินโควตา

## 4. ฟอรัมใน LAN / เครื่องตัวเอง

ฟอรัมของบริษัทมักรันในวงใน (`192.168.x.x`, `10.x.x.x`, `forum.local`) ซึ่งปกติ
relay จะ **บล็อก** เพราะเป็นที่อยู่ภายใน

ช่องทางฟอรัมทุกตัวจึงมีสวิตช์เดียว: **“เซิร์ฟเวอร์นี้อยู่ในเครื่อง/ในบ้าน”**
เมื่อเปิด ระบบจะยอมให้ยิงไปยังที่อยู่ private/LAN ของช่องทางนั้นเท่านั้น

สิ่งที่ยังถูกบล็อกเสมอ ไม่ว่าจะเปิดสวิตช์ใด:

- `169.254.0.0/16` (cloud metadata — จุดที่ใช้ขโมย credential ของเซิร์ฟเวอร์)
- `100.64.0.0/10` (CGNAT)
- ที่อยู่ reserved/ multicast / broadcast
- `http://` ไปยังปลายทางสาธารณะ และ URL ที่ฝัง username/password

สวิตช์นี้ผูกกับช่องทางที่ประกาศ `localAllowed` เท่านั้น — เปิดในไฟล์ credential ของ
`dev.to` ก็ไม่มีผล เพราะช่องนั้นไม่ได้ขอสิทธิ์นี้

## 5. ทำไมไม่ทำ “โพสต์ฟอรัมแทนคุณ” แบบเครื่องมือ auto‑post

เครื่องมือแบบที่เห็นขายกัน (สมัครที่เดียว แล้วโพสต์ได้ 200+ บอร์ด) ทำงานแบบนี้:

1. เขาสมัครบัญชีจำนวนมากบนบอร์ดนั้น ๆ ไว้ก่อน (บัญชีของเขา ไม่ใช่ของคุณ)
2. คุณจ่ายเงิน แล้วระบบใช้ **บัญชีของเขา** โพสต์ข้อความที่เขียนใหม่ (spin) พร้อมลิงก์ของคุณ
3. บอร์ดเหล่านั้นส่วนใหญ่เป็นฟอรัมร้าง/คุณภาพต่ำ และมักจ่ายเงินเพื่อให้ได้ลิงก์

ความเสี่ยงที่ต้องรู้:

- **Google spam policy (ฉบับ 2026)** ระบุชัดว่า *automated link creation* และ
  *forum comment link spam* เป็นการละเมิด และบทลงโทษ “link spam” เป็นแบบ
  **ติดลบถาวร** จนกว่าจะแก้ — คุ้มไหมกับการลิงก์จากบอร์ดที่ไม่มีคนอ่าน
- บัญชีที่คุณไม่ได้เป็นเจ้าของ = คุณควบคุมไม่ได้ว่าจะถูกลบเมื่อไหร่ และลิงก์จะหายไปทั้งชุด
- หลายเครื่องมือใช้ unique‑IP/proxy เพื่อหลบการตรวจจับ — ยิ่งแปลว่าเขารู้ว่ากำลังทำอะไรผิดกฎ

ทางที่ทำได้จริงและได้ผลกว่าสำหรับธุรกิจไทย: **เปิดฟอรัมของตัวเอง** (Discourse ติดตั้ง
บน VPS เริ่มต้นไม่ถึง 300 บาท/เดือน) แล้วโพสต์ผ่าน API ของช่องทางในหัวข้อ 2 —
ได้ทั้งลิงก์ถาวร ข้อมูลลูกค้า และไม่ต้องพึ่งบัญชีใคร

## 6. Pantip / Reddit / Facebook Groups — สถานะจริง

| แพลตฟอร์ม | สถานะ | สิ่งที่ทำได้ในแอปนี้ |
| :--- | :--- | :--- |
| **Pantip** | ไม่มี public API · สมาชิกอีเมลตั้งกระทู้ได้ 1/วัน · กระทู้ขายของต้องยืนยันบัตร ปชช. + ใช้งาน 3 เดือน | เตรียมข้อความ + เปิดหน้าเขียน + แสดงกฎก่อนกด |
| **Reddit** | จำกัด 100 QPM และปิดรับคำขอ API สาธารณะใหม่ตั้งแต่ 31 ต.ค. 2026 | กดเอง (มีลิงก์ submit เติมหัวข้อให้) |
| **Facebook Groups** | `publish_to_groups` ถูกถอดออกจากทุกเวอร์ชันตั้งแต่ 22 เม.ย. 2024 | ไม่มีเส้นทาง API — ใช้ Social Agency กับ **Page** แทน |

การโพสต์ซ้ำข้อความเดิมหลายห้อง (cross‑posting) เป็นสัญญาณ spam ที่ชัดที่สุด —
ถ้าจะใช้ Pantip จริง ให้เขียนเป็นคำถาม/ประสบการณ์จริงของธุรกิจ ไม่ใช่ประกาศขายล้วน

## 7. ตั้งค่าครั้งแรก — checklist ต่อช่องทาง

**Discourse**
1. Admin → Advanced → API keys → New API key
2. User level = Single User, สิทธิ์ Topics (write)
3. ใส่ URL ฟอรัม + Api-Key + Api-Username (+ category id ถ้าต้องการลงหมวด)

**XenForo**
1. Setup → API keys → Add key (ต้องเป็น super admin)
2. สิทธิ์ thread:write, ผูกกับผู้ใช้เจ้าของกระทู้
3. ใส่ URL + XF-Api-Key + node id (+ XF-Api-User เมื่อใช้ super user key)

**NodeBB** — เปิด `nodebb-plugin-write-api` → สร้าง token ใน ACP → ใส่ URL + token + cid

**Flarum** — Settings → Access tokens → สร้าง → ใส่ URL + token
(เว้น discussion id = ตั้งกระทู้ใหม่, ใส่ = ตอบในกระทู้เดิม)

**phpBB** — ติดตั้ง extension REST API (เช่น `dmzx/phpbbapi`) → สร้างคีย์ →
ใส่ URL + X-API-Key + forum id

**WordPress (ติดตั้งเอง)** — Users → Profile → Application Passwords → สร้าง →
ใส่ URL เว็บ + username + app password (ต้องเป็น HTTPS และไม่ปิด REST API)

**Bluesky** — Settings → App Passwords → สร้าง → ใส่ handle + app password
(ระบบขอ session ใหม่ทุกครั้ง ไม่เก็บ token ค้าง)

## 8. ข้อควรระวัง

1. **สิทธิ์ของคีย์** — สร้างคีย์ที่ผูกกับ *ผู้ใช้คนเดียว* และให้สิทธิ์เท่าที่ใช้จริง
   (สร้างกระทู้) อย่าใช้ admin key ทั้งระบบ
2. **HTTPS เท่านั้น** สำหรับฟอรัมสาธารณะ — ถ้าเป็น HTTP ระบบจะไม่ยอมส่ง
   (ยกเว้นเครื่อง/LAN ที่เปิดสวิตช์ในหัวข้อ 4)
3. **เนื้อหาซ้ำ** — โพสต์เดียวกันในหลายที่ควรตั้ง canonical กลับเว็บหลัก
   (WordPress/DEV ทำได้) หรือเขียนใหม่ให้ต่างจริง
4. **ภาษาอื่นใน API** — XenForo รับเฉพาะ form‑encoded, Flarum เป็น JSON:API
   ระบบจัดการให้แล้ว แต่ถ้าแก้ request เองต้องระวังจุดนี้
5. **คีย์หลุด** → revoke ที่ต้นทางทันที ระบบนี้ไม่ส่งคีย์กลับเบราว์เซอร์ แต่เก็บในเครื่องคุณ
6. **Bluesky 300 ตัวอักษร** — ลิงก์ที่วางในข้อความจะกดได้ก็ต่อเมื่อระบบสร้าง facet ให้
   ซึ่งแอปนี้ยังไม่ทำ → ใส่ URL ตรง ๆ ได้ แต่ผู้ใช้อาจต้องคัดลอกเอง
