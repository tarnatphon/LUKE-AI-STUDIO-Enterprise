# Social Agency · TikTok Direct Post (video)

This integration implements a **guarded, per-entry** TikTok Content Posting API `FILE_UPLOAD` flow. It does **not** grant TikTok app approval, OAuth authorization, `video.publish`, audit status, public posting, or token refresh. It does not upload anything to a real account during tests. Do not use a production token for the smoke tests.

## Requirements & setup

1. In TikTok for Developers, enable Content Posting API, request/obtain `video.publish`, and obtain **the intended creator's** User Access Token through TikTok authorization. This app accepts a manually provided token only (stored server-side in the existing `connectors.json` location, masked in UI); there is **no OAuth flow or refresh** here. Expired tokens must be replaced by an authorized operator. The connection test queries creator info; it does **not** prove app audit approval.
2. Under Connectors → TikTok, save the token; leave dry-run enabled until you intentionally want real sends. The `auditApproved` checkbox is an operator attestation, not an automated verification. Without it, the server rejects non-`SELF_ONLY` selections; TikTok also enforces its own account/app restrictions. Unaudited apps cannot post publicly; private-account/volume restrictions may apply even to private posts. Do not claim public support without TikTok audit.
3. Create a TikTok calendar entry, edit the caption, and generate a local MP4/MOV/WebM clip. Hosted URLs are not substituted for local files (`PULL_FROM_URL` would require a verified domain). Open the entry: creator info and available privacy options are retrieved on opening. The final outbound caption (including UTM link parameters) is previewed and can be edited before consent; **privacy has no default**. The operator chooses privacy, comments/Duet/Stitch settings, optional commercial disclosure (off by default; select Your brand and/or Branded content when enabled, never Branded content + SELF_ONLY), confirms music usage rights and explicitly authorizes this particular caption/video/account to be uploaded now or at its scheduled time. The app marks its own AI-generated clips with `is_aigc: true`. Re-consent after editing caption or regenerating video.
4. The Bangkok scheduler only picks TikTok entries with recorded per-entry consent; the ordinary AI review gate still applies. It does **not** automatically rotate TikTok into generated plans. A manual run before the scheduled time is a real run when dry-run is off; do not press Run unless you intend to send now. A dry-run is always marked as simulated, not published live. The access token must still be valid when a scheduled post becomes due. **No TikTok-native scheduled-post API is used.**

## Publishing & recovery

- Immediately before sending, the server re-queries creator info and verifies account, privacy option, maximum duration, caption and file hashes, commercial constraints, and audit attestation. URL tracking is added only to outbound caption links. TikTok caption links may not be clickable; use your analytics/landing-page logs to assess actual traffic.
- An `init` attempt is persisted **before** the network request. The app never automatically retries ambiguous init/upload failures, because a retry can duplicate a video. Once TikTok returns a `publish_id`, it is persisted before file transfer; returned upload URL is only accepted on HTTPS `open-upload.tiktokapis.com`. Sequential uploads use TikTok's chunk rules and `Content-Range`. If init fails ambiguously before an ID is returned, the entry is blocked from retrying; investigate in the TikTok app/developer tools rather than clearing state and guessing. If upload is uncertain, status polling is the safe next action, not another init.
- `publish_id` is a task identifier, **not** a public post ID or proof of publication. The entry remains `publishing` and the workflow remains `pending` until `/v2/post/publish/status/fetch/` reports `PUBLISH_COMPLETE` (then it becomes `published`), or `FAILED` (then it becomes `failed`). The scheduler polls up to five pending entries per tick (at most once per minute per entry); the drawer has a manual status-check button. Moderation can take hours. A private post need not return a public post ID. The API response field for public IDs is spelled `publicaly_available_post_id` by TikTok. Restart recovery never re-arms an entry after init was attempted. If the token expires during polling, update it; the entry remains pending and shows the error.
- TikTok does not expose per-post likes/comments/shares in this workflow. Those metrics are not invented; UTM reports count published links, not impressions/clicks.

## Local checks (no TikTok credentials)

`node scripts/server/social-agency-tiktok-smoke.cjs` stubs all outbound HTTPS and checks explicit consent, unaudited privacy, disclosure constraints, chunked file upload, AI flag, duplicate guards, pending/polling completion, caption invalidation and crash recovery. Also run the existing social agency smoke tests and `cd app/frontend && npm run build`.
